# Bookshelf 2.0 — plan and decisions

This folder holds the agreed direction for the 2.0 rework. Read this file first when picking the work back up.

- `prototype.html` — the clickable design study (desktop and mobile, day and evening). Open it in a browser. It is a design reference, not app code: its data is built in and every server action is acted out.
- Live copy: https://claude.ai/artifact/4oRGjkGhDJNBr5hSA8Qm9t
- `notes-study.html` — the design study for 2.1's notes (a book's notes page, the editor, All notes, the notes parts of Settings, Markdown export, Kindle import), desktop and phone. Open it in a browser; `#notes-phone`, `#timeline`, `#settings` and the like open a screen directly.

## Ground rules

- 2.0 is a clean break. Bookshelf 1.x was a terminal app that built a static website; 2.0 is a self-hosted web app (a server in Docker, or a plain program) that serves the shelf and its admin. Nothing of 1.x carries over. The owner's 1.x library is moved over once by a script kept outside the repository (decided 2026-10-11: 1.x had no other users, so 2.0 holds no code for it).
- No dead code. Not carried over: the terminal interface, the static-site build, the shelf/stack/coverflow view switch, scroll speeds, the random-book button, the footer setting, the site subtitle ("tagline"). Old code may be reused where it is good (covers, thumbnails, spine colours, archives, import/export, backups), but only what 2.0 uses.
- Runs anywhere Docker runs (any NAS, Unraid, Synology, a VPS, a Raspberry Pi) and without Docker on Linux, macOS and Windows. Nothing may assume one platform.
- The website's copy is in American English.
- Never write to the owner's real 1.x library (`~/.local/share/bookshelf`); test against copies.

## Architecture (agreed 2026-10-12)

- **Server:** Go, one program. Serves the site, the admin and a JSON API from the same address. Builds into a small Docker image that runs as a non-root user (`PUID`/`PGID`).
- **Storage:** SQLite in one file, through a pure-Go driver (no cgo, so cross-builds stay simple). Covers and backups are plain files beside it. Everything lives in one data folder (`/data` in Docker).
- **Frontend:** a hybrid.
  - The shelf and the open book stay as a self-contained plain-JavaScript engine, ported from the study. It creates each spine once and only moves it, runs the flights with hand-built Web Animations, keeps text-bearing elements off compositor layers, and moves the eye with the book. A framework must never re-render these elements.
  - Everything around them is Svelte (with Vite): the header, settings, Add a book, the edit form, the stats page, sign-in, cards, sheets, toasts. They talk to the engine through a small explicit interface (open a book, refresh a spine, re-lay the shelves, put the book back).
  - Node is needed only to build the frontend; the Docker image builds it once and runs Go alone. The built files are embedded in the Go program.
- **Sign-in:** like Inkubator. `BOOKSHELF_ADMIN_USER` (default `admin`) and `BOOKSHELF_ADMIN_PASSWORD` in the container's settings. Week-long session per device (HTTP-only cookie). Lockout for 15 minutes after repeated wrong passwords. The password changes by changing the variable and restarting. The server refuses to start without a password.
- **Privacy is enforced by the server**, not by hiding controls: hidden books, and everything when the library is private, never leave the server for visitors.
- **Go** is chosen on the merits (decided 2026-10-12), not to match another project: a small fast HTTP server and image work (covers, thumbnails, spine colours) from the standard library, one self-contained cross-built program for every platform and Docker, and pure-Go SQLite. Reusing the good 1.x code is a bonus.

## Storage safety on Unraid (lesson from Inkubator 3.0.1)

On Unraid a data folder under `/mnt/user` goes through `shfs`, a FUSE layer with few worker threads. Inkubator 3.0.0 took a blocking file lock on every request; a burst of requests (a page of thumbnails) left every `shfs` worker waiting on the lock while the holder needed one to read its file, so `/mnt/user` deadlocked and Docker, the Unraid interface and network shares hung with it (Inkubator commit 68e499b). SQLite by default locks on every transaction, and its WAL mode needs a shared-memory file that FUSE and network filesystems handle badly, so Bookshelf must be built so this cannot happen:

- **One lock, taken once.** The database is opened at startup with `locking_mode=EXCLUSIVE` and that lock is held for the life of the program; no request ever waits on a file lock. A second Bookshelf on the same folder is refused at once with "another Bookshelf is already using …".
- **No shared-memory file.** In exclusive mode SQLite keeps the WAL index in heap memory; no `-shm` file is used. (Exclusive mode is set before the first access to the WAL database, and the journal mode is chosen accordingly; verify with a test.)
- **Requests don't touch the database.** The visitor-facing library (and the owner's) is kept in memory and rebuilt after a change; changes take turns on an in-process mutex and are written in one transaction. Covers and thumbnails are plain file reads.
- **Test:** hundreds of concurrent public and signed-in requests against a scratch library, asserting every answer succeeds and the process holds exactly one file lock throughout.
- **Docs:** the Unraid guide suggests `/mnt/cache/appdata/bookshelf` (or an exclusive appdata share), which bypasses `shfs`; troubleshooting explains the "already using" message. A hand edit of the database while Bookshelf runs is not supported (restore a backup instead).

## Design decisions (settled in the study)

**The shelf**
- One view on desktop and phone: thin, rounded wood planks on a coloured wall, spines coloured from their covers.
- Spine width follows the page count (`max(18, min(80, pages × 0.085 + 7))`), so the thinnest spine is about 21px. Every spine shows its title and its author's surname; the author line shortens before it can crowd the title.
- Spine height follows the title's length (`196 + 3.1 × characters`, clamped 222–280) with a few units of per-book irregularity; hardcover and cloth ×1.07, leather ×1.05. Real dimensions are not used (rarely in the catalogues).
- Bindings: paperback, hardcover, cloth, leather. There is no mass-market binding: mass market counts as paperback. Each binding keeps the spine in its cover's own colour; only texture and details differ (hardcover: rounded with hinge creases and board edges; cloth: woven texture, gilt lettering; leather: grain, gilt lettering, raised bands at head and tail, lettering kept clear of the bands). Can be turned off (Look → Show bindings on the spines).
- Hover: the spine rises a few whole pixels with a deeper shadow and a light, the same for every book wherever it stands. Position only, never a transform or opacity change on the spine (those make the lettering re-settle). Instant, no intent delay.
- Click: the book flies off the shelf, turns to face you and opens to a title page. Put back retraces the same path. Esc mid-flight turns the flight round; it is never queued.
- Select mode: chosen books show a slip of paper rising out of their top, plus an inner ring. Books never move.
- The book being read hangs a ribbon from the foot of its spine over the plank, and the ribbon rises with the spine on hover.
- The bookcase, each part on its own, all in the shelf wood: shelves (the planks, on by default), sides, top, back panel. Sides stand on the bottom plank; only without shelves does a base board close the bottom. With no parts at all the books stand in rows on their own (decided 2026-10-13).

**The open book**
- Left board: the cover plate in the cover's own proportions, the endpaper tinted from the spine colour. Right page: set like a title page (running head with binding, title sized to its length, subtitle split at the first ":", a lozenge in the book's colour, author in small caps, a dotted-leader colophon, the actions, a folio).
- Actions: Copy link, Search on … (one source: a "Search on X" action; several: a "Search on…" row that swaps in place, sharing one slot with the actions and the Remove question so nothing moves), and for the owner Edit, Reading now/Finished reading, Hide from website, Remove (asks on the page, then Undo).
- Edit happens on the title page itself: the same layout as fields; ISBN checksum and year/pages validation; Enter saves, Esc cancels. Cover tools on the inside board (replace cover, spine colour by hand, back to the cover's colour); on a phone a "Replace cover" bar sits on the cover at the head of the page.
- On a phone the open board runs off the left edge and the cover appears small at the head of the page; tapping it zooms it, tapping again puts it back.
- Books opened from the stats page open there: they rise from their cover, with no Previous/Next, and go back to it.

**Header**
- The site name (a link home, accent colour on hover) and, beside it, the tools in a fixed place: Search, sort (Author/Title/Year), day/evening, Stats, and for the owner Select, Add book, Settings, Sign out; for visitors Sign in. Search is an icon that grows into a field on click/tap (never hover) as an overlay toward free space, so nothing moves; Esc clears, then folds; Enter on an empty field folds.
- Beneath: "Now reading <title> by <author>" with a tiny cover on the left, the owner's social links on the right.
- On a phone: the title with Add book (owner, a plus), Search, and a menu button on one line; the menu sheet holds sort, day/evening, Statistics, Select, Settings, Sign in/out.

**Adding a book**
- ISBN lookup (Open Library, then Google Books) or a barcode scan (the camera, reading by itself). Duplicates are caught ("Show it"). Unknown or invalid ISBNs offer entry by hand. A confirm card with the cover and every field editable, then the shelf scrolls to the book's place and the existing opening animation opens its details once (review candidate, corrected after owner testing, 2026-10-22).
- A book without a cover gets a plain cloth cover with its title stamped on.
- ISBNs are normalised on entry (labels and punctuation stripped, ISBN-10 converted to ISBN-13), stored as bare digits and always shown hyphenated by the ISBN agency's range table (the server ships RangeMessage.xml).
- Periodicals (decided 2026-10-11): some periodicals publish book-like issues, which carry an ISSN rather than an ISBN. The field is "ISBN or ISSN" and takes either, or a periodical's 977 barcode (read back to its ISSN). An ISSN is checked by its own check digit and shown as `ISSN 1300-2880`; such a book also has an issue (as printed, `70–71`). The same issue can't be shelved twice; other issues of the same periodical can. An ISSN can't be looked up, so it goes straight to entry by hand with the ISSN filled in. Books with an ISSN take their address from the title.

**Stats page** (`#stats`, the Stats icon; off for visitors if the owner turns it off)
- Now reading first, under its own heading: cover, title, progress (share and page on the left, the owner's page field on the same line at the right, the bar beneath), and four facts (days since starting, pages to go, share of the library that is shorter, share that is older).
- The library in numbers: five uniform tiles (books, pages, authors, average length, years written), then books by decade (only decades that have books, labels fitted to the room), by page band, by binding, in translation, authors with two or more books, top publishers, and the oldest/newest/longest/shortest books.
- One accent hue, hairline grids, a Table view for every chart, hover readouts that only repeat what the table holds.

**Reading** (designed 2026-10-11, study v47–48)
- Any number of books can be read at once, each with its own ribbon. The header names one book with its author, two by title ("Now reading A and B"), more as "A and 2 more", with their small covers fanned; with several, it opens a short list (cover, title, author, share read) to choose from. The stats page has a "Now reading" card per book, one beneath another (side by side broke the card's facts row).
- On a book's page (owner): "Reading now" and "Mark as read" when it isn't being read; "Finished reading" and "Set aside" while it is. Finishing offers "Add a note" in its toast; setting aside can be undone.
- Mark as read: a small card (like sign-in) asking when it was finished (on a day, in a year, or "I don't remember"); its toast offers "Add a note".
- The line above the title reads "Paperback · Read twice" (or "Reading now"); it is information only.

**A book's notes page** (2.1, designed 2026-10-12, study v49; replaces 2.0's Readings card, which went stale and was cramped):
- Its own page at `/<book address>/notes`, reached from a **Notes** action on the book's page (the book closes onto the page's cover, as it does back to the stats page; the cover opens it again, solo). Esc goes back to the shelf.
- At the top: cover, binding and reading line, title, author, translator · publisher · year · pages.
- Notes and highlights are entries of their own, any number per book. A note is the owner's words; a highlight is a passage as printed, an optional page and an optional thought on it. Each is private by default or public, and names the reading it came from (the one under way, or the last, by default; or none). Filters (All · Notes · Highlights) and order (Newest · By page) appear only when there is something to choose between. One form writes a new entry at the top or edits one in place; deleting can be undone. With two or more readings, entries and readings are named by their place ("Second reading").
- Beside them, the owner's readings as a timeline, newest first: the one under way (page field, progress, Finished, Set aside), then each ended one (dates, days read counting both ends, so one day is "In one day"; pages a day; where a set-aside reading stopped; Edit, Delete). Deleting a reading keeps its entries, untied. On a phone the readings fold into one summary line above the notes.
- Visitors see the page only for a book with something public, and only the public entries, never readings or which reading an entry came from. The notes blog (later) can draw from public entries.

**Notes, second take** (2.1, decided 2026-10-14 with the owner; where it differs from the section above, this wins, and the notes page is to be redesigned from scratch rather than from study v49):
- **One kind of entry.** No note/highlight distinction. An entry is a jotting on a book: a passage as printed, the owner's words, or both (a note can carry a passage, a passage a note), any number per book, written in whatever manner the owner likes. Only one of the two is required. Schema 3 drops `kind`.
- **Capture** (kept easy, never in the way): quick capture is undecided (the small jotting card was tried in study v2 and dropped on 2026-10-14; it is to be rethought, not redesigned); import of Kindle's `My Clippings.txt` (and later Apple Books/Goodreads), matched to books by title; photographing a page is left to the phone's own text scanning (iOS "Scan Text" in a field), **no OCR in the app**: the app stays small. Tested with a made-up clippings file kept as a test fixture.
- **Notes are always about a book in the library**; this is not a micro-blog for anything else. For the owner they live on the book. The "All notes" timeline (every book's notes, newest first; nothing is written there, but the owner can edit a note in place, in the same editor, decided 2026-10-15) is always the owner's, with its own icon in the header beside Stats (a row in the phone's menu); visitors get it, icon included, only while the owner turns it on in Settings (off by default), and then the owner can look at it as visitors do (decided 2026-10-15, after first hiding it from the owner too while off); not a link in Settings or the footer.
- **Where, not page:** an entry's place is optional, and is a page, a chapter or a location (Kindle gives locations; a location may be a range), always a number. By page order sorts pages and locations by their number; chapters and notes without a place follow, newest first.
- **Sharing and publishing, simple:** Markdown export per book and for all books. A link to one entry, to a book's notes, or to the owner's whole notes timeline, each only if the owner allows it.
- **Privacy, granular:** each entry is private or public; a book's notes can be hidden from visitors as a whole; and the notes can be kept from visitors altogether (no notes pages at all). Enforced by the server, like the rest.
- The notes editor (study review, 2026-10-14, fifth pass): a fixed window for your thoughts, always there. Under it, two toggles, + Passage and + Page: each adds its own field (the passage below your words so far; the place, a number with a small kind button: Page, Ch. or Loc.) and tapping again removes it. Then who can read it ("Only me" / "Public", as in Settings) and Save. Which reading a note belongs to is never asked: it joins the one under way. Every control you tap shares one height, 36px with a pointer and 44px on a phone. On a phone the editor starts as one line ("Write a note") and opens in place. Notes are edited in place after an Edit link; while editing, + Passage and + Page add the missing parts, with the Only me / Public button, Delete and Done. Controls come in three kinds: a filled button commits, an outlined button adds or sets something on a note, a plain text link acts on a note; text that isn't underlined is information.
- A book's notes page is as wide as the shelf (the same 1200px box as the header). Its left column is the book's cover, title and author, nothing more; the notes take the rest. The book's own page (tap the cover or title) holds the details and, while the book is being read, the owner's progress (bar and page field) with Finished reading and Set aside. The owner sees the editor, "Only me" marks, Edit on each note and one ⋯ menu beside the order switch (how many notes visitors can read, hide or show the book, Copy link, Download Markdown, and for a book read more than once a choice of reading and a "Group by reading" switch). Notes are never grouped by reading unless that switch is on; each note from one of several readings says so in its own line ("2nd reading", owner only), and choosing a reading in ⋯ filters the list, with a chip in the header to clear it. All notes has the same header (count, view switch, ⋯). How a book shows it has notes: on the book's page, as a count, not on the shelf (decided 2026-10-14).
- Visitor settings are exceptions, not a list: Settings → Visitors lists only hidden books and finds one by title or author to hide; the export picker is the same finder (most recently noted books until you type). Designed for hundreds of books.
- The editor is one flow, and an entry is up to three parts in order: words before the passage, the passage, words after it (schema: `pre`, `quote`, `text`). Writing words and then pressing + Passage puts the passage on a new line below them (no extra blank line if there is one already); Tab leaves the passage for a new line below it. Hiding the passage keeps what was typed. Page is a button that turns into its own field when tapped (and folds back if left empty). The footer is one row of the app's own buttons (`.btn`, no pills) that never change size (on a phone they are icons only, four equal columns: Passage, Page, Only me/Public, Save; editing adds Delete and ends in Done); Page is a button ("+ Page", then a small "Page" button inside it with the number to its right) that takes digits only, and tapping the small button switches it between Page, Chapter and Loc. (the place of an entry is one of those three, always a number); the note window keeps its size when a passage opens and grows only as the text needs; a typed draft has an × that discards it with Undo; Delete is a red trash icon button on the date line, its right edge in line with Done; editing a note uses the composer's own surface and footer. Covers drawn by the app for a book without a picture carry no title or rule in cards, the sidebar and timelines (decided 2026-10-14). Editing a note uses the same window and footer, with the same × (discards the edits; Undo in the toast; Done is refused while the note is empty). Chapter shows as “Ch.” in the Page button. An emptied passage stays empty; its text returns only by pressing Passage again in the same session. The Passage icon is a bar with lines (how a passage looks in a note), not quote marks.
- Still to design together: quick capture (the jotting card was dropped), Markdown in entries, chapter/location sorting.

**Settings** (redesigned for 2.0.5, 2026-10-13, from a demo the owner reviewed; a page since 2026-10-15, designed for it from a second demo the owner reviewed: "sections as pages" with each group a card): a heading like Statistics' and All notes', then the sections down the side, staying in sight as the page scrolls, the one shown marked there and carrying no title of its own; each section has its own address (`/settings/visitors`; `/settings` shows the first on a wide screen, under `/settings/shelf`). Each group of settings is a card on the wall, as the charts are, and the shelf preview a card that stays in sight. On a phone `/settings` lists the sections with a line on what each holds, and each opens as its own page under "‹ Settings" (back to the list when it came from there) and its name. The header's Settings icon toggles it like Statistics; Esc or the library's name returns to the shelf. Rows of name | control under small-caps captions, with no rules between them, a short line under a caption where its settings need explaining, the app's own controls throughout (switches, segments with one sliding highlight, swatches, wells, fields). Every change shows at once and saves itself; a quiet "Settings saved" pill says so. Nothing animates when a section is merely opened, only on the owner's own change.
- Shelf: Day | Evening (which paint, wood and ribbon are being chosen; each is set for day and for evening, decided 2026-10-13), then a preview of the shelf from the library's own books, drawn by the shelf's own CSS at the wide screen's scale and scaled down whole, like a picture, into a box of fixed height (sized for the tallest books the settings allow, so no setting resizes it); it stays pinned, with Day | Evening, while the choices scroll. When no book is being read, one book wears the ribbon as a sample so its colour shows. Paint, wood and ribbon (paints for the half of the day being chosen, or any colour from the rainbow well; the nine woods; the ribbon's colour, swatches or the rainbow well); Bookcase (shelves, sides, top, back panel); Books (binding details, size, spine height).
- Header and footer: name (inline Markdown, a hidden feature: nothing in the sheet says so), icon, icon beside the name; links under the name (Goodreads, The StoryGraph, Instagram, no others); footer text (inline Markdown) and Show the footer. A new library has no footer: empty and off.
- Visitors: Access (private library; statistics; what is never shown); When they arrive (theme: Automatic, Day, Evening; sort and its direction); A book's page (address: ISBN, Hyphenated or Title, with the example as its hint); Search links (Open Library, Google Books, Goodreads, a switch each).
- Your library: import (CSV, JSON, a Bookshelf archive), export (CSV, JSON, full archive with covers), backups (how often, how many to keep, the list, back up now, restore). Backups live in the data folder.
- About: Account (signed in as …, sign out; the password is changed where Bookshelf runs); Version (the version and whether a newer one is out, check for updates); Bookshelf (one sentence on who made it and that its code is free, then Website and GitHub links).
- Colours are picked in a panel of the app's own under the well (lib/colorpicker.js), for the walls, the ribbon and a book's spine: the browser's own picker opened wherever the window system put it (a corner of the screen on the owner's Linux desktop).

**Interaction rules (both platforms, one system)**
- Cards or pages (decided 2026-10-15): a card is for a short step about what is on screen (a question, a choice, a small form about this book or this shelf; you come back exactly where you were). A page is for a place or a task of its own (long, in sections, worth an address). Sign in and Settings are pages; Add book, Mark as read, Export and the phone's menu are cards; the open book is its own view. One thing never behaves differently by platform unless it has to.
- History (decided 2026-10-15): Back and Forward work as on any site. Every place is a step: each page, each Settings section, each book taken out, and each book stepped to with Previous and Next (so Back returns to the book before). Put back (or Esc, or a click beside the book) goes back past all of them to the page the book was taken out over. Cards, sorting, searching as you type, day or evening and choosing books are not steps; Back with a card open closes it with the page it was over. Leaving a page by its icon or the library's name is a step like any link. Signing in goes back to the page it was asked for from, so Back never lands on the form. A step a reader may not see (a visitor at `/settings`) shows the shelf in its place. Each step remembers how far down its page was. The first page of a visit has nothing before it, as on any site.
- Layers (the open book, cards, sheets): while one is open the page beneath doesn't scroll (CSS only, nothing pinned or measured); backdrops ignore swipes; each layer keeps its own scrolling.
- Typing on a touch screen: nothing focuses a field for the reader; tapping a field's caption doesn't select it; tapping anything that isn't a field puts the keyboard away; Safari brings the field in use into view itself (nothing of ours moves a field for the keyboard). Cards float, standing off the page by their shadow and edge (on a phone at the foot of the screen, clear of every edge and above the home indicator), dim the page as the open book does, and keep their own size. Fields are at least 16px on phones (no iOS zoom). Hover effects only where a pointer can hover.
- Focus returns to a spine after closing a book only for keyboard users.

**Typography:** Source Serif 4 (headings, book details, notes) and Instrument Sans (interface), both bundled. Its optical size follows the type size by itself. Fraunces, used until 2.1, was dropped on 2026-10-15 for reading comfort: the owner compared a dozen faces in a type trial and chose Source Serif 4 as the tightest on a phone.

## Data model (draft for review)

`books`
| Field | Notes |
| --- | --- |
| id | stable id |
| title, subtitle-free title | the title as entered; the title page splits at ":" |
| author, translator, publisher | text |
| published | year (integer) |
| pages | integer; sets spine width |
| binding | paperback, hardcover, cloth, leather |
| isbn | bare ISBN-13 digits, unique when present |
| issn, issue | a periodical's ISSN (bare eight characters) and its issue; the pair is unique; never with an ISBN |
| slug | from the title, unique (`-2`, `-3` on clashes) |
| hidden | hidden from visitors |
| cover | file in the data folder, with a thumbnail; null for a plain cloth cover |
| spine_color, spine_text_color | worked out from the cover on the server |
| spine_color_override | the owner's own colour, or null |
| added_at, updated_at | timestamps |

No edition field: the ISBN identifies the edition (decided 2026-10-12).

`readings` — every time a book is read (decided 2026-10-12: keep as much reading data as possible; the stats page can choose what to show)
| Field | Notes |
| --- | --- |
| id | |
| book_id | the book |
| started_at | when "Reading now" was chosen |
| ended_at | when it was finished or set aside; null while reading |
| outcome | reading, finished, set aside |

Several books can be read at once (decided 2026-10-11), each with its own ribbon; a book has at most one reading in progress, so "Reading now" on a book already being read changes nothing. Re-reads are separate readings. How long a book took is `ended_at − started_at`.

**Mark as read** (decided 2026-10-12): any book can be marked as read without having been tracked, since most books on a shelf were read before Bookshelf or without "Reading now". It creates a finished reading whose dates are as precise as the owner gives: a date, only a year, or none ("I don't remember"). So the dates are stored with a precision (`day`, `year`, `unknown`), and untracked readings have no page log. Such a reading counts as read (and can carry a note) but is left out of pace and time-to-finish figures; one with a year still counts toward that year. A book is "read" when it has at least one finished reading.

**Re-reading** (decided 2026-10-12): a book can be read any number of times. "Reading now" on a book already read starts a new reading; "Mark as read" on a book already marked adds another. Earlier readings are never changed by a new one. Each reading keeps its own dates, page log and note. Any past reading can be edited (dates, outcome) or deleted, to correct mistakes. Stats can count both distinct books read and readings (so re-reads are their own figure), and a book's page can show how many times it was read with each reading and its note.

`reading_progress` — the page log of a reading: reading_id, page, at. Written whenever the owner sets their page, so pace (pages per day), days actually read and progress over time can be worked out later. The current page is the latest entry.

`entries` (schema 3, Bookshelf 2.1; schema 2 replaced 2.0's `notes`, one per finished reading) — the owner's notes, any number per book: id, book_id, reading_id (nullable; set to null when its reading is deleted), pre (words before the passage), quote (a passage as printed), text (the owner's words, after the passage if there is one), where_kind (`page`, `chapter`, `loc` or empty), where_n, where_to (the end of a location range), public, created_at, updated_at. A note needs a passage or some words; words with no passage are kept in `text`. Opening a 2.0 library moves each note across as a note tied to its reading; schema 2's notes keep their words, its highlights their passage and thought, and a page becomes a place of kind page. Archives are format 3 since (format 2's entries and format 1's notes are read the same way).

`books.notes_hidden` (schema 3) — the book's notes are kept from visitors, public or not.

`settings` — one row of key/value pairs for everything in Settings. Notes add `notes` (visitors may read public notes; on), `timeline` (visitors may open All notes; off) and `startsPublic` (a new note starts public; off).
`sessions` — signed-in devices (token hash, created, last seen, expires).
`sign_in_attempts` — for the lockout.
`backups` — recorded in the data folder as files; the list is read from there.

## API (draft for review)

Public (what visitors may see; the server filters hidden books and refuses everything when the library is private):
- `GET /api/library` — books, the public settings and the current reading.
- `GET /covers/<id>` and `/covers/<id>/thumb`.

Owner (signed in):
- `POST /api/session`, `DELETE /api/session`.
- `POST /api/books`, `PATCH /api/books/<id>`, `DELETE /api/books/<id>`, batch hide/show/remove.
- `PUT /api/books/<id>/cover` (upload), `DELETE /api/books/<id>/cover`.
- `GET /api/lookup?id=` (Open Library, then Google Books, through the server; an ISSN answers `periodical: true` with the ISSN read). Books are sent with one `identifier` field (ISBN or ISSN) and an `issue`; they come back with `isbn`, `issn`, `issue` and `identifier` (as shown).
- `POST /api/readings` (start reading a book, or mark it as read with an optional date or year), `PATCH /api/readings/<id>` (set the page, finish, set aside, correct dates), `DELETE /api/readings/<id>`, `GET /api/readings` (the history, optionally for one book).
- `GET /api/books/<id>/entries` (a book's notes, oldest first: all for the owner; for visitors only the public ones, without their reading, and nothing for a hidden book, a book whose notes are hidden, notes switched off, or a private library), `POST /api/books/<id>/entries`, `PATCH /api/entries/<id>`, `DELETE /api/entries/<id>` (owner). An entry is sent as `pre`, `quote`, `text`, `where` (`{kind, n, to?}` or null), `readingId`, `public`. Entries aren't in the library view, which carries only a count per book (`entries`: public ones visitors may read), and for the owner `notesHidden`, `notesPublic` and `notesLast` (when the newest was written), so a long notes history never weighs on the shelf. Undo puts an entry back with its `createdAt`.
- `PATCH /api/books/<id>/notes` (`{hidden}`: keep a book's notes from visitors, owner).
- `GET /api/notes` (All notes, newest first, 100 at a time; `before` and `beforeId` page on): the owner gets everything, or with `view=visitors` what visitors would see; visitors only when `notes` and `timeline` are on and the library isn't private.
- `GET /api/notes/export?book=&private=1&download=1&tz=` (owner): Markdown, one book's (with front matter) or every book's, dated in the reader's time zone.
- `POST /api/notes/import?preview=1&public=1&tz=` (owner): the body is a Kindle `My Clippings.txt`; with `preview` it only says what it read, matched and would add; `tz` is the reader's time zone (Kindle writes its own clock's time).
- `GET/PATCH /api/settings`.
- `POST /api/import` (a Bookshelf archive, CSV or JSON; answers with how many books were added and skipped), `GET /api/export?format=csv|json|archive`.
- `GET /api/backups`, `POST /api/backups`, `POST /api/backups/<name>/restore`.
